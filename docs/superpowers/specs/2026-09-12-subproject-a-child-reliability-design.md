# Design: Подпроект A — «Ребёнок и надёжность»

**Дата:** 2026-09-12
**Статус:** утверждён (в чате, brainstorming)
**Объём:** заметки к замеру, напоминания ребёнку с эскалацией, настраиваемые часы напоминаний, меню ребёнка, кнопка бэкапа БД.
**Не входит (другие подпроекты):** streak/геймификация (B), PDF-отчёт (C).

---

## 1. Контекст

Бот пикфлоуметрии для семьи (1 ребёнок + 2 родителя), aiogram 3.x + SQLite.
Проблемы, которые решает этот подпроект:

- Колонка `note` есть в прод-БД, кодом не используется — провалы в красной зоне не объяснимы.
- Напоминания о пропусках получают только родители (10:00/22:00), а замер делает ребёнок.
- Часы напоминаний захардкожены в `config.py`.
- У ребёнка в меню одна кнопка «Измерение»; `stats`-хендлер недостижим.
- Единственный экземпляр медицинской БД, бэкапов нет.

## 2. Заметки к замеру

### Поток
После сохранения нового замера (`_save_measurement`) бот спрашивает:
«Добавить заметку?» — кнопки `📝 Да` / `Пропустить`.

- `📝 Да` → FSM-состояние `Measurement.waiting_note` (в FSM-данных `note_for_id`) → любой текст ≤ 200 символов → `set_note()` → «✅ Заметка сохранена» → главное меню.
- `Пропустить` → главное меню без вопросов.
- Текст во время `waiting_note` от ребёнка или родителя — сохраняется как заметка (кто нажал «Измерение», тому и вопрос).

### Отображение
- История: после значения — `ℹ️ <текст>` (в той же строке).
- Сводка дня: под каждым замером с заметкой.
- CSV: новая колонка «Заметка» (после «Добавил»).
- Недельный отчёт: без изменений (не включать, чтобы не раздувать).

### database.py
```python
def set_note(db_path: str, measurement_id: int, note: str, user_id: int) -> bool:
    # UPDATE measurements SET note = ? WHERE id = ? AND user_id = ?
```
`user_id` = CHILD_ID (все записи принадлежат ребёнку). Существующие `SELECT *` возвращают `note` автоматически.

### FSM
- Новое состояние: `Measurement.waiting_note`.
- Возврат: после сохранения или `/cancel`-подобной кнопки «⬅️ Пропустить».

## 3. Напоминания ребёнку + эскалация

### Новая схема (часы — дефолты, берутся из settings)
| Время | Кому | Условие | Текст |
|-------|------|----------|-------|
| 08:00 | ребёнок | нет утреннего замера | «☀️ Привет! Пора сделать утренний замер 💨» |
| 20:00 | ребёнок | нет вечернего замера | «🌙 Пора сделать вечерний замер 💨» |
| 10:00 | оба родителя | нет утреннего замера | как сейчас + «(напоминание в 08:00 было)» |
| 22:00 | оба родителя | нет вечернего замера | как сейчас |

- Ключевой сценарий: ребёнок замерил в 09:15 после пинга 08:00 → в 10:00 `has_today_measurement` = True → родителям ничего не идёт.
- Флаги дедупликации: новые колонки `child_morning_reminder`, `child_evening_reminder` в `reminders_sent` (миграция try/except ALTER в `init_db`).
- Типы напоминаний в `mark_reminder_sent`/`was_reminder_sent`: `"child_morning"`, `"child_evening"` (+ существующие).
- Отправка ребёнку обёрнута в try/except pass (как у родителей).

## 3b. Автозаполнение при пропуске (auto-carry, добавлено 2026-09-12)

**Мотивация (из практики семьи):** ребёнок ленится вводить замер ежедневно; дневник рвётся.

**Схема:** в час эскалации родителям (10:00 / 22:00, настраиваемый), если замер отсутствует:

1. Бот создаёт запись с ПСВ последнего замера того же времени суток (утро←последний утренний, вечер←последний вечерний) и пометкой `source='auto'`.
2. Запись отображается везде с суффиксом `🤖 авто` — в истории, сводке дня; в CSV — колонка «Источник» со значением `авто`.
3. **График, статистика (`get_stats`), тренды, недельные сравнения — авто-записи НЕ учитываются** (фильтр `source != 'auto'` в выборках статистики и графика). Врач видит сплошной календарь замеров, но аналитика строится только на реальных данных.
4. **Напоминания родителям не отменяются, но меняют тон** — вместо «напомните» приходит: «⚠️ Утренний замер пропущен — записали как вчера (240 🤖, не измерено). Скорректируйте, если знаете реальное значение».
5. **Корректировка (ключевое требование владельца):** когда ребёнок позже делает реальный замер, для слота, где стоит авто-запись:
   - `cb_add` видит, что слот занят **авто**-записью → не спрашивает «всё равно/исправить», а **перезаписывает** авто-запись реальным значением (`source='manual'`, `note=None`).
   - Родитель может отредактировать/удалить авто-запись кнопками ✏️/🗑️ как любую другую.
   - `«✏️ Исправить последний»` работает и для авто-записей.
6. Авто-запись создаётся **1 раз на слот** (флаг `auto_filled_morning/evening` в `reminders_sent`-стиле: колонки `auto_morning`, `auto_evening` в reminders_sent за дату). Ручной замер после авто — просто перезапись той же записи.

### Реализация
- Миграция `measurements`: колонка `source TEXT DEFAULT 'manual'` (try/except ALTER).
- `database.py`:
  - `add_measurement(..., source='manual')` — параметр.
  - `get_last_measurement_of_tod(db, uid, tod)` — последний замер данного времени суток (для значения авто).
  - В `get_stats`, `get_measurements_for_chart`, `get_last_two_weeks` — `AND (source IS NULL OR source != 'auto')`.
  - `replace_auto_measurement(db, uid, tod, pef, added_by)` — UPDATE авто-записи сегодняшнего слота на ручную (или отдельный флаг в `cb_add`).
  - `has_today_measurement(..., skip_auto=True)` — авто не считается «измерением» для напоминаний.
- `bot.py`:
  - В `scheduler_loop` на эскалационных тиках: если нет замера → создать авто-запись → отправить родителям информирование (не «напомните») → пометить флаг.
  - `cb_add`: при занятом слоте проверить, не авто ли запись (`source=='auto'`) → перезапись без вопроса «всё равно?».
  - История/сводка: суффикс `🤖` если `source=='auto'`.
- Зоны/проценты в самой авто-записи НЕ считаются и НЕ уведомляются (никаких красных/жёлтых алертов на скопированном значении).

### Дополнительные тесты
13. Авто-запись создаётся со значением последнего замера того же tod и `source='auto'`.
14. `get_stats`/chart игнорируют авто-записи.
15. Ручной замер после авто перезаписывает запись (не создаёт дубль).
16. Напоминание родителям при авто-записи содержит «авто»/«скорректируйте», а НЕ «напомните».
17. Авто не создаётся дважды в один слот (флаг дедупликации).
18. `has_today_measurement(skip_auto=True)` → авто не считается замером.

## 5b. График с навигацией по месяцам (добавлено 2026-09-12)

**Мотивация:** график — одна картинка за 30 дней, «плоский»: нельзя заглянуть глубже в историю (в БД 183 замера, ~3 месяца).

### UI
- `cb_chart` строит график **текущего месяца** (календарный месяц, не «последние 30 дней»).
- Под картинкой — навигация:
  - «⏮️ Предыдущий месяц» (`chart_<YYYY-MM>`) — идём вглубь истории
  - Заголовок месяца в подписи: «📊 Motya — Сентябрь 2026»
  - «⏭️ Следующий месяц» — только если месяц < текущего (из будущего строить нечего)
  - «⬅️ Назад» — в меню.
- Родитель и ребёнок — один и тот же график (у ребёнка теперь тоже есть кнопка, см. §5).

### Рендер
- `get_measurements_for_month(db, uid, year, month)` — выборка по диапазону дат `YYYY-MM-01 ≤ measured_at < YYYY-MM+1-01` (диапазон, не LIKE — индекс работает).
- Если в месяце < 2 замеров: PNG не строим, текст «📊 В <месяц> было меньше 2 замеров» + навигация (не тупик).
- Существующие элементы сохраняются: линия, точки утро/вечер, best/worst-аннотации, линии нормы и зон.
- Авто-записи (`source='auto'`) на график не попадают (см. §3b).

### Данные
- `database.py`: `get_measurements_for_month(db_path, user_id, year, month) -> list` и `get_available_months(db_path, user_id) -> list[(year, month)]` — для отображения первого доступного месяца при заходе «слишком глубоко» и для лимита навигации.

## 6. Кнопка бэкапа БД

⚙️ → «💾 Скачать бэкап» (только родители):
1. Временный файл `backup_<CHILD_NAME>_<ГГГГММДД_ЧЧММ>.db` рядом с БД (или tempfile).
2. Копирование через `sqlite3.connect(src).backup(dst)` — консистентно даже при WAL.
3. Отправка документом с caption «💾 Бэкап БД: N замеров» (N = count).
4. Удаление временного файла (try/finally).

`database.py`: `backup_db(db_path, dest_path)` + `count_measurements(db_path, user_id)`.
Кнопка в `cb_settings` — новая строка клавиатуры.

## 7. Миграции

В `init_db()` (стиль проекта — try/except):
```python
# reminders_sent: флаги child-напоминаний и авто-заполнения
for col in ("child_morning_reminder", "child_evening_reminder", "auto_morning", "auto_evening"):
    try: ALTER TABLE reminders_sent ADD COLUMN <col> INTEGER DEFAULT 0
    except OperationalError: pass
# measurements: пометка источника записи (manual/auto)
try: ALTER TABLE measurements ADD COLUMN source TEXT DEFAULT 'manual'
except OperationalError: pass
```

## 8. Обработка ошибок

- `set_note` / `backup`: ошибки → «❌ Не удалось…» + лог, бот не падает.
- Ввод часа: не цифра или вне 0–23 → «Введите число 0–23» (состояние сохраняется).
- Заметка длиннее 200 → обрезать до 200 с уведомлением «(обрезано)».
- Отправка напоминаний: каждый `send_message` в try/except.
