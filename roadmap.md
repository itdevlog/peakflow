## 🔴 Критические баги (исправить в первую очередь)

### 1. «✏️ Исправить последний» не работает для родителей
- **Где:** `bot.py:430` → `edit_measurement(DB_PATH, mid, new_val, callback.from_user.id)`
- **Суть:** `edit_measurement()` (`database.py:101`) обновляет запись только при совпадении `user_id` записи (= `CHILD_ID`) с переданным ID. Родитель передаёт свой ID → `rowcount = 0` → всегда «❌ Не удалось изменить запись».
- **Фикс:** передавать `CHILD_ID` (как это уже сделано в `_save_edit_any`, `bot.py:452`), либо добавить в `database.py` отдельную функцию родительского редактирования. Тест `test_edit_measurement` этого не ловит, потому что там пользователь совпадает с владельцем записи.

### 2. `mark_reminder_sent()` стирает другие флаги дня
- **Где:** `database.py:284-287`
- **Суть:** `INSERT OR REPLACE INTO reminders_sent (date) VALUES (?)` заменяет всю строку, сбрасывая `morning_reminder`/`evening_reminder` в 0. Пример: утреннее напоминание отправлено в 10:00, в 21:00 недельный отчёт делает REPLACE — флаг утра теряется.
- **Фикс:** `INSERT INTO reminders_sent (date) VALUES (?) ON CONFLICT(date) DO NOTHING` + отдельный `UPDATE ... SET <type> = 1`.

### 3. Планировщик может пропустить напоминание на весь день
- **Где:** `bot.py:1126, 1143, 1159`
- **Суть:** условие `hour == DEADLINE and minute == 0` при `sleep(60)` — если тик пришёл в 10:00:59, следующий будет 10:01:59, и окно `minute == 0` закрыто. Напоминание молча не уйдёт (флаг `was_reminder_sent` тоже не ставится, но час уже прошёл).
- **Фикс:** проверять `hour == DEADLINE and minute < 2`, либо хранить время последнего тика и сравнивать «перешли ли мы границу часа», либо использовать `aiogram.utils.schedule_jobs` / APScheduler.

### 4. Двойной `callback.answer()` → TelegramBadRequest
- **Где:** `bot.py:872` + `925` (`cb_chart`), `939` (`cb_summary`), `982` (`cb_weekly`), `1043` (`cb_stats`), `763` (`cb_export`)
- **Суть:** в начале хендлера вызывается `await callback.answer()`, а затем `respond()`/`answer_callback()` вызывает `answer()` второй раз на тот же callback query — Telegram вернёт ошибку.
- **Фикс:** убрать первый `answer()` или не вызывать `answer()` внутри `answer_callback`, если уже отвечено.

### 5. `del_confirm_*` без проверки прав
- **Где:** `bot.py:614-629`
- **Суть:** `cb_delete` проверяет `is_parent()`, а подтверждающий хендлер `cb_delete_confirm` — нет. Сейчас риск низкий (бот отвечает только трём ID), но защита должна быть на этапе подтверждения, а не на этапе показа кнопки.
- **Фикс:** добавить ту же проверку `is_parent(callback.from_user.id)`.

## 🟠 Надёжность и корректность данных

### 6. Молчаливая перезапись времени суток
- **Где:** `bot.py:369-370` (`_save_measurement`)
- **Суть:** если слот `auto_time_of_day()` уже занят и `forced_tod` не задан, замер молча записывается как противоположное время суток. Например, замер в 10:30 при уже сделанном утреннем попадёт в БД как «Вечер». Искажает статистику утро/вечер.
- **Фикс:** записывать реальное время и считать оба замера «утренними» (счётчик, а не булев флаг), либо всегда явно спрашивать пользователя.

### 7. Блокирующие вызовы в async-хендлерах
- **Суть:** все SQLite-операции и генерация matplotlib-графика (`bot.py:888-923`) выполняются синхронно в event loop. На больших объёмах данных бот замирает для всех пользователей.
- **Фикс:** `asyncio.to_thread(...)` для тяжёлых операций, либо переход на `aiosqlite` + одно долгоживущее соединение (сейчас на каждый запрос открывается новое соединение + `PRAGMA journal_mode=WAL` — 8–10 соединений на одно действие пользователя).

### 8. Небезопасный парсинг callback_data
- **Где:** `bot.py:547, 587, 616, 638, 476, 489`
- **Суть:** `int(callback.data.replace(...))` без `try/except` — любой неожиданный payload уронит хендлер.
- **Фикс:** обернуть в хелпер `parse_int()` с безопасным fallback.

### 9. Состояние FSM «залипает»
- **Где:** `bot.py:1091-1096` (`catch_all`)
- **Суть:** во время `pef_input_*` или `editing_target_pef` ввод текста молча игнорируется (`if current: return`). Пользователь не понимает, что делать. В `editing_target_pef` нецифровой ввод вообще не обрабатывается (`F.text.isdigit()` не матчится).
- **Фикс:** добавить хендлеры на «нецифровой ввод» для всех состояний с подсказкой и кнопкой отмены.

### 10. Дрейф схемы БД
- **Суть:** продакшн-база `peakflow.db` создана старой версией кода: есть таблицы `users`, `parent_child_links`, колонка `note`, а `time_of_day` с DEFAULT `'unknown'`. Текущий `init_db()` ничего из этого не знает и не синхронизирует. Миграции сделаны через `try/except ALTER` — без версионирования.
- **Фикс:** ввести `PRAGMA user_version` + явные миграции; вычистить или задокументироватьlegacy-таблицы.

### 11. Нет индексов
- **Суть:** в БД нет ни одного явного индекса; все запросы фильтруют по `user_id` + `measured_at` через `LIKE 'YYYY-MM-DD%'`.
- **Фикс:** `CREATE INDEX IF NOT EXISTS idx_meas_user_time ON measurements(user_id, measured_at)` (рекомендация уже есть в PROJECT.md, но в код не добавлена). Заодно заменить `LIKE` на диапазон `measured_at >= today AND < tomorrow` — индекс будет работать.

## 🟡 Качество кода

### 12. Дублирование SQL в обход `database.py`
- **Где:** `_save_edit_any` (`bot.py:451`), `cb_edit_any` (`bot.py:589`), `cb_delete`/`cb_delete_confirm` (`bot.py:617, 641`)
- **Суть:** прямой `sqlite3.connect()` в `bot.py`, хотя `database.py` уже имеет `edit_measurement`/`delete_measurement`. При этом `delete_measurement` и `get_week_measurements` нигде не используются.
- **Фикс:** вся работа с БД — только через `database.py`; мёртвый код удалить.

### 13. Два `get_effective_target()`
- **Где:** `bot.py:105` затеняет импортированный из `config.py:69`. Плюс `except (ValueError, Exception)` — избыточный кортеж.
- **Фикс:** оставить одну реализацию (в `database.py`, т.к. она читает settings), импорт убрать.

### 14. `TZ_OFFSET` читается в двух местах независимо
- **Где:** `config.py:11` и `database.py:7` — оба читают env напрямую. Изменение в одном месте не затронет другое.
- **Фикс:** единый источник (config), в `database.py` — импорт. Долгосрочно — перейти на `zoneinfo` (`Europe/Yekaterinburg`) вместо ручного смещения (DST/переводы часов).

### 15. Мёртвый код и неиспользуемые константы
- `safe_delete` (`bot.py:156`), `_show_history_from_message` (`bot.py:817`), `Measurement.waiting_delete_confirm` (`bot.py:98`), `PEF_NORM_BY_AGE` и `get_effective_target` из config, `ZONE_RED = 50` (`config.py:44`, порог красной зоны реально `< 60` = `ZONE_YELLOW`, а в PROJECT.md описан как `< 60%` — определение противоречит использованию).
- **Фикс:** удалить или начать использовать (например, ZONE_RED — если по врачу красная зона действительно < 50%, то и эмодзи, и алерт должны использовать её).

### 16. Markdown на пользовательских данных
- **Суть:** `parse_mode="Markdown"` с `CHILD_NAME` и значениями из env — `_` или `*` в имени сломают рендер.
- **Фикс:** `DefaultBotProperties(parse_mode=ParseMode.HTML)` + `html.escape()`.

### 17. CSV-экспорт без экранирования
- **Где:** `bot.py:774-787`
- **Суть:** ручная склейка строк — запятая/кавычка в `CHILD_NAME` или имени ломает файл.
- **Фикс:** модуль `csv` с `QUOTE_ALL`.

## 💡 Что можно улучшить (по категориям, с приоритетом)

### Функциональность (то, чего не хватает пользователям)

1. **Меню для ребёнка** — сейчас у ребёнка одна кнопка «Измерение». График, история и статистика есть только у родителей. Ребёнку полезно видеть свой тренд — это ещё и мотивация.
2. **Напоминания самому ребёнку** — сейчас о пропусках узнают только родители. Логично напоминать в 20:00 самому исполнителю, а родителям — только если он не среагировал (эскалация).
3. **Настройка времени в ⚙️** — часы напоминаний (8/10/20/22) и день отчёта захардкожены в `config.py`, хотя таблица `settings` уже есть и используется для целевой ПСВ. Добавить «⏰ Время напоминаний» рядом с «🎯 Изменить цель».
4. **Заметки к замеру** — колонка `note` уже есть в БД, но кодом не используется. «Болел», «после спорта», «забыл лекарство» — именно это объясняет провалы в красной зоне.
5. **Мультидет** — таблица `users` с ролями `parent`/`child` и `parent_child_links` уже существует в прод-БД. Сейчас бот жёстко заточен под одного `CHILD_ID` из `.env`.

### UX (мелочи, которые заметны каждый день)

6. **Кнопка «Назад» на шаге десятков** — её физически нет в `kb_pef_tens()` (`bot.py:234`), хотя хендлер для неё написан (`bot.py:508`). Пользователь застрял, если промахнулся.
7. **Отмена в FSM** — ввод текста во время выбора ПСВ молча игнорируется. Нужна подсказка «Введите число или нажмите Отмена».
8. **Меню не обновляется, а плодится** — каждый callback удаляет старое сообщение и шлёт новое. Лучше `edit_message` для того же экрана: меньше мусора в чате.
9. **Экспорт в Excel-friendly вид** — CSV уже есть, добавить период «за N дней» и график в PDF-отчёт для врача (matplotlib уже подключён).

### Архитектура / надёжность

10. **Убрать блокирующий I/O из event loop** — SQLite-вызовы и построение графика в `asyncio.to_thread()`, долгоживущее соединение вместо connect/close на каждый запрос.
11. **Индекс + отказ от `LIKE`** — `idx_meas_user_time ON measurements(user_id, measured_at)` и диапазонные запросы вместо `LIKE 'YYYY-MM-DD%'`.
12. **Версионированные миграции** (`PRAGMA user_version`) — сейчас схема живой БД разошлась с кодом (`users`, `note`), и это никак не отслеживается.
13. **`zoneinfo` вместо `TZ_OFFSET`** — ручное смещение сломается при любом переводе часов.
14. **Бэкап БД** — данные медицинские, а файл один. Кнопка «📥 Скачать бэкап» для родителей + периодический `sqlite3 .backup` — 20 минут работы.

### Инфраструктура

15. **`.gitignore` + `.env.example`** — токен и медданные сейчас в риск-зоне при любом `git init`/публикации.
16. **Запуск как systemd-сервис** — flock-лок есть, но автоперезапуск при падении отсутствует (а падать есть на что: непарсируемый callback_data роняет хендлеры).
17. **Pinned-зависимости + pytest в CI** — `aiogram>=3.0.0` слишком свободно, тесты на чистой машине не запустятся.
