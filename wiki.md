## 1. Назначение и общий принцип

Бот ведёт дневник пикфлоуметрии ребёнка:

- **Ребёнок или любой родитель** жмёт «💨 Измерение» и выбирает значение ПСВ кнопками (без набора текста).
- Время суток (утро/вечер) определяется **автоматически** по текущему часу.
- Бот вычисляет **зону** (зелёная/жёлтая/красная) как % от целевой ПСВ и показывает динамику.
- **Родители** дополнительно видят историю, график за 30 дней, сводку дня, недельный отчёт, могут редактировать/удалять любые записи и менять целевую ПСВ.
- Бот **уведомляет** родителей: о каждом новом замере, о красной зоне, о пропущенных замерах (10:00 / 22:00), еженедельный отчёт (воскресенье 21:00).

> ⚠️ Бот — инструмент мониторинга, не медицинское устройство; решения о лечении принимает врач.

## 3. Конфигурация (.env и config.py)

### Переменные `.env`

| Переменная | Обяз. | По умолч. | Описание |
|------------|:-----:|:---------:|----------|
| `BOT_TOKEN` | ✅ | — | Токен от @BotFather (без него `main()` завершается) |
| `CHILD_ID` | ✅ | `0` | Telegram ID ребёнка (при `0` — выход) |
| `PARENT_IDS` | ❌ | `0,0` | ID родителей через запятую (все нули → выход) |
| `CHILD_NAME` | ❌ | `Ребёнок` | Имя ребёнка в сообщениях |
| `TARGET_PEF` | ❌ | `260` | Целевая ПСВ от врача (fallback для БД) |
| `DB_PATH` | ❌ | `peakflow.db` | Путь к SQLite-файлу |
| `TZ_OFFSET` | ❌ | `5` (UTC+5) | Смещение часового пояса в часах |
| `WEBAPP_HOST` | ❌ | `0.0.0.0` | Адрес прослушивания веб-сервера Mini App |
| `WEBAPP_PORT` | ❌ | `8080` | Порт веб-сервера; `0` — веб-сервер выключен |
| `WEBAPP_URL` | ❌ | — | Публичный HTTPS-URL Mini App; пусто — кнопка Mini App не добавляется |

### Константы `config.py`

| Константа | Значение | Смысл |
|-----------|:--------:|-------|
| `ZONE_GREEN` | `80` | ≥ 80% от цели → 🟢 зелёная зона |
| `ZONE_YELLOW` | `60` | 60–79% → 🟡 жёлтая; **< 60% → 🔴 красная** |
| `ZONE_RED` | `50` | Задекларирован, но в логике зон не используется |
| `PEF_NORM_BY_AGE` | dict | Справочник норм по возрасту 4–18 лет (кодом не используется) |
| `REMINDER_MORNING_DEADLINE` | `10` | 10:00 — дедлайн утреннего замера |
| `REMINDER_EVENING_DEADLINE` | `22` | 22:00 — дедлайн вечернего замера |
| `WEEKLY_REPORT_DAY` | `6` | Воскресенье (0=Пн … 6=Вс) |
| `WEEKLY_REPORT_HOUR` | `21` | 21:00 — час недельного отчёта |

### Хелперы `config.py`

- `is_parent(uid)` — True, если ID входит в `PARENT_IDS`.
- `is_child(uid)` — True, если ID == `CHILD_ID`.
- `get_effective_target()` — `TARGET_PEF or 300` (в bot.py переопределён своей версией, читающей БД, см. ниже).

### Часовой пояс

- `bot.py`: `TZ = timezone(timedelta(hours=TZ_OFFSET))`, `now_tz()` — текущее локальное время.
- `database.py`: независимо читает `TZ_OFFSET` из env и пишет `measured_at` **в локальном времени** строкой `"%Y-%m-%d %H:%M:%S"` (не UTC, не ISO).

## 4. Роли и разграничение доступа

Все пользователи известны заранее по ID — **регистрации нет**.

| Роль | Как определяется | Возможности |
|------|------------------|-------------|
| 👶 Ребёнок | `is_child(uid)` | «💨 Измерение» — единственная кнопка главного меню |
| 👨‍👧 Родитель | `is_parent(uid)` | Всё: измерение, история, график, сводка, неделя, настройки, исправить последний, редактирование/удаление любых записей, экспорт |
| Посторонний | не родитель и не ребёнок | `/start` → «⚠️ Этот бот только для семьи» — дальше доступа нет |

Проверки прав в хендлерах:

- `cb_edit_any`, `cb_delete`, `cb_delete_confirm`*(частично)*, `cb_settings`, `cb_change_target` — только для родителей (`is_parent`), иначе alert «Только родители…».
- **Все измерения пишутся от имени ребёнка**: в БД `user_id` = `CHILD_ID` всегда, а ID того, кто нажал кнопки, хранится в `added_by`.

## 5. База данных (SQLite)

Подключение (`database.py: get_connection`): `sqlite3.connect` + `row_factory=Row` + `PRAGMA journal_mode=WAL` — **новое соединение на каждый запрос**.

### Таблица `measurements`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INTEGER PK AUTOINCREMENT | ID записи |
| `user_id` | INTEGER | Всегда `CHILD_ID` |
| `pef_value` | INTEGER | Значение ПСВ, л/мин (100–690) |
| `time_of_day` | TEXT, CHECK `morning`/`evening` | Время суток |
| `measured_at` | TIMESTAMP | Локальное время записи `ГГГГ-ММ-ДД ЧЧ:ММ:СС` |
| `added_by` | INTEGER | Telegram ID добавившего (для 👨‍👧/👶 в истории) |

### Таблица `reminders_sent`

| Поле | Описание |
|------|----------|
| `date` (PK) | Дата `ГГГГ-ММ-ДД` |
| `morning_reminder` | Отправлено ли напоминание о пропуске утреннего замера |
| `evening_reminder` | То же для вечернего |
| `weekly_report` | Отправлен ли недельный отчёт в этот день |

Назначение — защита от повторной отправки в течение дня (планировщик тикает каждую минуту).

### Таблица `settings`

Ключ-значение (`key`, `value`). Единственный используемый ключ — `target_pef` (создаётся при `init_db` со значением `260`). Хранит целевую ПСВ, изменяемую родителями через бота.

### Миграции в `init_db()`

- `CREATE TABLE IF NOT EXISTS` для трёх таблиц.
- `try/except ALTER`: добавление `time_of_day` (старые записи → `morning`) и `added_by` — для совместимости со старой схемой. Версионирования миграций нет.
- В прод-БД есть legacy-таблицы (`users`, `parent_child_links`, колонка `note`), которые текущий код не использует.

### Функции `database.py`

| Функция | Возвращает / делает |
|---------|---------------------|
| `init_db(path)` | Создание таблиц, миграции, дефолт `target_pef`, индекс `idx_meas_user_time` |
| `add_measurement(db, pef, tod, uid, by)` | INSERT; возвращает `id` |
| `edit_measurement(db, mid, val, uid)` | UPDATE по `id`+`user_id`; bool |
| `delete_measurement(db, mid, uid)` | DELETE по `id`+`user_id`; bool |
| `get_last_measurement(db, uid)` | Последняя запись (`ORDER BY id DESC LIMIT 1`) |
| `get_all_measurements(db, uid)` | Все записи, новые сверху |
| `get_today_measurements(db, uid)` | Записи за сегодня (`LIKE 'ГГГГ-ММ-ДД%'`), по возрастанию времени |
| `has_today_measurement(db, uid, tod)` | Есть ли запись «сегодня + время суток» |
| `get_week_measurements(...)` | ⚠️ нигде не используется (мёртвый код) |
| `get_last_two_weeks(db, uid)` | `(эта_неделя, прошлая)` от понедельника 00:00 |
| `get_measurements_paginated(db, uid, page, per_page)` | `(страница, всего, всего_страниц)`; по 10 записей |
| `get_measurements_for_chart(db, uid, days=30)` | Данные за N дней, по возрастанию |
| `get_stats(db, uid)` | Полная статистика (см. §15) |
| `mark_reminder_sent` / `was_reminder_sent` | Флаги отправленных напоминаний по дате (INSERT … ON CONFLICT DO NOTHING — соседние флаги дня не затираются) |
| `get_setting` / `set_setting` | Чтение/запись `settings` |

## 6. Жизненный цикл: запуск, singleton-lock, планировщик

### `main()` (bot.py:1180)

```
1. Валидация: BOT_TOKEN задан? CHILD_ID ≠ 0? PARENT_IDS не все нули? (иначе sys.exit(1))
2. acquire_lock()  — защита от второго экземпляра (flock на .bot.lock, неблокирующе)
3. init_db(DB_PATH)
4. dp.startup.register(on_startup)  → при старте поллинга создаёт задачу scheduler_loop()
5. dp.run_polling(bot)              → long polling
6. при выходе — release_lock() (unlock + удаление .bot.lock)
```

Если бот уже запущен — второй процесс пишет в лог «Бот уже запущен!» и завершается.

### Локальное время

Все отметки `measured_at` и логика «сегодня» — в `TZ_OFFSET` (по умолчанию UTC+5).

## 7. FSM-состояния

`bot.py`, класс `Measurement(StatesGroup)`:

| Состояние | Когда активно | Выход |
|-----------|---------------|-------|
| `pef_input_hundreds` | Пользователь выбирает сотни ПСВ (клавиатура 1–6) | Выбор `h_N` → `pef_input_tens`; `back` → главное меню (state.clear) |
| `pef_input_tens` | Пользователь выбирает десятки (00–90) | Выбор `t_NN` → сохранение по контексту → state.clear |
| `editing_target_pef` | Родитель вводит текстом новую целевую ПСВ | Ввод цифры 100–800 → сохранение; state.clear |
| `waiting_delete_confirm` | ⚠️ объявлено, но не используется (мёртвый код) | — |

Данные FSM (`state.update_data`):

- `input_context` — **ключевое поле**: `"add"` | `"edit_last"` | `"edit_any"` — определяет, что делать с введённым числом после выбора десятков.
- `forced_tod` — время суток при повторном замере (`add_force_`).
- `hundreds` — выбранная разряд сотен.
- `edit_id` — ID редактируемой записи.

## 8. Клавиатуры (UI)

Все меню — **inline-кнопки** под сообщением (reply-клавиатур нет). Формат вывода — Markdown.

| Функция | Содержимое |
|---------|-----------|
| `kb_main(is_parent)` | Ребёнку: только «💨 Измерение». Родителю: Измерение / История / График / Сводка / Неделя / Настройки / ✏️ Исправить последний |
| `kb_back()` | «⬅️ Назад» (callback `back`) |
| `kb_pagination(page, total, is_parent, items)` | Строки «✏️ N | 🗑️» для каждой записи (только родители) + навигация ⏮️ `N/M` ⏭️ + низ: Назад (+ Настройки для родителей) |
| `kb_pef_hundreds()` | Ряд: `1 2 3 4 5 6` + «⬅️ Назад». Callback `h_1`…`h_6` |
| `kb_pef_tens()` | 2 ряда: `00 10 20 30 40` / `50 60 70 80 90` + ряд «⬅️ Назад». Callback `t_00`…`t_90`, `back` |

Диапазон вводимого ПСВ = **100–690** (сотни 1–6 × десятки 00–90).

## 9. Главное меню и статус-блок

### `build_status_block()` — текст главного меню

```
👋 *Motya* | Целевая: 260 л/мин

Сегодня: ☀️ 240 🟢 | 🌙 —
Последний: 240 🟢 (+10)
```

- Считывается **всё** из БД: сегодняшние утро/вечер, разница с предыдущим замером.
- Эмодзи времени суток в коде: ☀️ (утро) / 🌙 (вечер) — `tod_emoji()`.
- Строка «Последний: …» добавляется только если замеров ≥ 2 (разница `+N`/`-N` л/мин).

### `send_main_menu()`

Вход в меню: если вызвано из callback — `answer_callback()` (ACK + удаление старого сообщения), затем новое сообщение со статус-блоком и `kb_main(роль)`. Вход текстом — то же через `message.answer()`.

> UX-паттерн всего бота: **старое сообщение удаляется, новое отправляется** (чаты не «обновляют» сообщения, кроме шага сотни→десятки, где используется `edit_text`).

## 10. Логика добавления измерения

### Вход: `cb_add` (callback `add`)

1. `auto_time_of_day()` → `hour < 12` ? `morning` : `evening`.
2. **Если замер этого времени суток уже есть сегодня** (`has_today_measurement`):
   - показ «⚠️ уже измерено сегодня» с кнопками:
     - «✅ Всё равно ☀️» → `add_force_<tod>` (сохранит как повторный замер этого же времени суток);
     - «✏️ Исправить» → `edit_last`;
     - «⬅️ Назад».
3. Иначе: `input_context="add"`, сообщение «Выбери ПСВ (л/мин), ☀️ Утро (определено автоматически), Диапазон: 100–690», клавиатура сотен, состояние `pef_input_hundreds`.

### `cb_add_force_` (callback `add_force_morning|evening`)

FSM: `input_context="add"`, `forced_tod=<tod>` — повторный замер: слот уже занят, но записываем ещё раз в то же время суток.

### Шаг 1: `cb_select_hundreds` (callback `h_N`, состояние `pef_input_hundreds`)

- `h` сохраняется в FSM (`hundreds`).
- Сообщение **редактируется** (`edit_text`): «Выбрано: `N__` л/мин, теперь десятки» + `kb_pef_tens()`.
- Состояние → `pef_input_tens`.

### Шаг 2: `cb_select_tens` (callback `t_NN`, состояние `pef_input_tens`)

- `pef = hundreds*100 + NN` (например `2` + `40` = `240`).
- Диспетчеризация по `input_context`:

| `input_context` | Функция сохранения |
|-----------------|--------------------|
| `"add"` | `_save_measurement()` |
| `"edit_last"` | `_save_edit_last()` |
| `"edit_any"` | `_save_edit_any()` |

### `_save_measurement()` — сохранение нового замера

```
1. Время суток:
   forced_tod есть?  → берём его (повторный замер)
   иначе             → auto_time_of_day();
                       если этот слот занят → МОЛЧА инвертируем утро↔вечер (⚠️ см. §24, п.6)
2. add_measurement() → INSERT (user_id=CHILD_ID, added_by=кто нажал)
3. Ответ: «✅ ☀️ Утро: *240* л/мин 🟢 / Зона: Зелёная (92% от нормы) / 📈 Изменение: +5»
   (изменение = разница с ПРЕДПОСЛЕДНИМ замером)
4. Уведомление «📝 <кто> добавил для *Motya*: 240 л/мин 🟢 (Утро)»
   → всем родителям, КРОМЕ добавившего
5. ЕСЛИ pct < ZONE_YELLOW (60%) → 🚨 алерт красной зоны ВСЕМ родителям
   («Свяжитесь с врачом») — независимо от того, кто добавил
6. state.clear() → главное меню
```

## 11. Логика редактирования записей

### «✏️ Исправить последний» (`edit_last`) — родитель и ребёнок

- Берётся `get_last_measurement()` (последняя запись ребёнка).
- Если записей нет → «📭 Нет измерений для исправления».
- FSM: `edit_id`, `input_context="edit_last"`, показ старого значения, клавиатура сотен → десятков.
- `_save_edit_last()`: `edit_measurement(DB_PATH, mid, new_val, CHILD_ID)` — запись принадлежит ребёнку, поэтому `user_id` передаётся всегда `CHILD_ID` (работает и для родителей, и для ребёнка).

### Редактирование любой записи (`edit_<id>`) — только родитель

- Хендлер `cb_edit_any` перехватывает все `edit_*` кроме `edit_last` (проверка равенства — хак, т.к. `startswith("edit_")`).
- Проверка `is_parent` → иначе alert.
- Чтение записи прямым SQL (в обход `database.py`), показ «✏️ Запись #id: …», FSM: `edit_id`, `input_context="edit_any"` → ввод сотен/десятков.
- `_save_edit_any()`: прямой `UPDATE ... WHERE id=? AND user_id=CHILD_ID` — здесь `user_id` передаётся верно (CHILD_ID), поэтому для родителей работает.
- После сохранения — возврат в историю (`_show_history_from_callback`, страница 1).

## 12. Логика удаления записей

Только родители. Точка входа — кнопки «🗑️» в истории (`del_<id>`).

### Шаг 1: `cb_delete` (callback `del_<id>`)

1. Проверка `is_parent` → иначе alert «Только родители могут удалять».
2. Чтение записи прямым SQL; если нет → alert «Запись не найдена».
3. Подтверждение: «⚠️ Удалить запись #id? ☀️ 240 л/мин (дата). Это действие необратимо!»
   - «🗑️ Да, удалить» → `del_confirm_<id>`
   - «❌ Отмена» → `history`

> Порядок регистрации хендлеров важен: `del_confirm_` зарегистрирован **раньше** `del_`, т.к. aiogram матчит по порядку (иначе `del_confirm_123` поймался бы как `del_` + мусор).

### Шаг 2: `cb_delete_confirm` (callback `del_confirm_<id>`)

- Проверка `is_parent` → иначе alert «Только родители могут удалять» (защита и на этапе подтверждения).
- Прямой `DELETE FROM measurements WHERE id=? AND user_id=CHILD_ID`.
- Результат — alert «✅ Запись удалена» / «❌ Не удалось», затем `state.clear()` и возврат в историю (стр. 1).

## 16. Недельный отчёт

📋 *Motya* — неделя 2026-09-07 — 2026-09-13

## 18. Зоны ПСВ и расчёты

| Функция | Логика |
|---------|--------|
| `pef_zone(value, target)` | `pct = value/target*100`. `pct ≥ 80` → 🟢 «Зелёная»; `60 ≤ pct < 80` → 🟡 «Жёлтая»; `pct < 60` → 🔴 «Красная» |
| `pct_of(value, target)` | Целочисленный % от нормы (защита от деления на 0 → 100) |
| `auto_time_of_day()` | Час < 12 → `morning`, иначе `evening` |

Соответствие медицинской практике: зелёная зона ≥ 80% от личного максимума — контроль; жёлтая 60–79% — осторожность; красная < 60% — опасность. Порог красной зоны в коде фактически = `ZONE_YELLOW` (60%), а не `ZONE_RED` (50%).

## 19. Уведомления

| Событие | Триггер | Кому | Текст |
|---------|---------|------|-------|

## 20. Планировщик: напоминания и авто-отчёты

`scheduler_loop()` (bot.py:1115) — async-задача, запускается на старте поллинга:

```
loop каждые 60 секунд:
    now = локальное время (TZ)

    ── 10:00–10:01 (hour==10 and minute<2, окно is_reminder_minute) ──
    если флаг morning_missing за сегодня НЕ ставился:
        если утреннего замера сегодня нет →
            уведомить всех родителей, mark_reminder_sent(morning_missing)

    ── 22:00–22:01 ──
    аналогично для evening_missing

    ── воскресенье 21:00–21:01 ──
    если флаг weekly за сегодня не ставился:
        text = _send_weekly_report()
        если есть данные → разослать родителям, mark_reminder_sent(weekly)

    исключения ловятся и логируются (цикл не умирает)
```

Дедубликация — по таблице `reminders_sent` (один флаг на дату на тип события). Двухминутное окно `is_reminder_minute()` компенсирует дрейф `sleep(60)`: точный тик 10:00:00 не гарантирован, но любой тик в первые 2 минуты часа сработает; повторные срабатывания подавляются флагами.

## 26. Веб-слой (Mini App) и эксплуатация (`manage.sh`)

### Веб-слой в процессе бота

Веб-сервер поднимается **в том же процессе и event loop**, что и long polling
aiogram (отдельного сервиса/порта процессов нет). Слой включается, когда
`WEBAPP_PORT > 0`.

| Модуль | Что делает |
|--------|-----------|
| `web/api.py` | `create_app(services)` — FastAPI-приложение. `GET /healthz` (health-check); read-only API SP2a (`/api/me`, `/status`, `/summary`, `/history`, `/chart`, `/stats`, `/weekly`); запись SP2b (`POST /api/measurements`, `PATCH`/`DELETE /api/measurements/{id}`, `POST …/note`); настройки/экспорт SP2c (`/api/settings*`, `/api/export/*`, `/api/backup`) |
| `web/server.py` | `run_webapp(services)` — запускает uvicorn на `WEBAPP_HOST:WEBAPP_PORT` и обслуживает приложение; `wait_forever()` — режим без веб-сервера (ожидание сигнала завершения) |

#### Mini App (SP2a): чтение

- `web/auth.py` — проверка HMAC-подписи Telegram `initData` (заголовок
  `X-Telegram-Init-Data`); доступ только у `CHILD_ID` и `PARENT_IDS`, иначе 403.
- `web/api.py` — read-only эндпоинты: `/api/me`, `/api/status`, `/api/summary`,
  `/api/history`, `/api/chart`, `/api/stats`, `/api/weekly`.
- `web/static/` — `index.html`, `app.js` (vanilla JS + Telegram WebApp SDK,
  интерактивный график на `<canvas>`), `style.css`.
- Кнопка «💨 Дневник» ставится в `bot._setup_menu_button()`, если задан
  `WEBAPP_URL`. Наружу биндить только за Caddy (HTTPS обязателен для initData).

#### Mini App (SP2b): запись

- `POST /api/measurements` — добавить замер (`{pef}`, 100–690): авто-время суток,
  замена авто-записи, ответ `{id, pef, tod, zone, pct, diff}`; уведомляет родителей.
- `PATCH /api/measurements/{id}` / `DELETE /api/measurements/{id}` — только родители.
- `POST /api/measurements/{id}/note` — заметка (≤200 символов), обе роли.
- `web/notify.py` — Telegram-уведомления (паритет с ботом, no-op без бота).
- `bot._web_services` передаёт `bot` в web-слой.

#### Mini App (SP2c): настройки, CSV, бэкап (только родители)

- `GET/PUT /api/settings`, `PUT /api/settings/target` (100–800),
  `PUT /api/settings/reminders` (часы 0–23).
- `GET /api/export/periods`, `GET /api/export/csv?period=all|YYYY-MM`
  (UTF-8 BOM, те же колонки, что в боте), `GET /api/backup` (согласованный
  `sqlite3.backup`, файл удаляется после отдачи).
- `report.py` — общие чистые хелперы (`pef_zone`, `pct_of`, `month_title`,
  `parse_month`, `build_csv_content`, `display_name`); `bot.py` ре-экспортирует
  их для совместимости.
- Фронтенд: таб «⚙️ Настройки» (скрыт у ребёнка), скачивание через fetch+blob.

Конфигурация — переменные `.env` (`config.py`): `WEBAPP_HOST` (по умолчанию
`0.0.0.0`), `WEBAPP_PORT` (по умолчанию `8080`; `0` — выключено), `WEBAPP_URL`
(публичный HTTPS-URL; пусто — кнопка Mini App не добавляется). Health-check
`GET /healthz` используется командами `manage.sh status`/`doctor`.

### `manage.sh` — установка и эксплуатация

`manage.sh` — единая точка установки и ops. Быстрый старт без ручного
клонирования (каталог по умолчанию `/opt/peakflow`):

```bash
curl -fsSL https://raw.githubusercontent.com/itdevlog/peakflow/main/manage.sh | bash -s -- install
```

| Команда | Назначение |
|---------|-----------|
| `install` | venv (`.venv`), зависимости, интерактивный `.env`, systemd-сервис `peakflow-bot` |
| `update` | `git pull` с бэкапом и откатом при неудачном health-check |
| `start` / `stop` / `restart` | Управление сервисом или ручным процессом |
| `status` | Статус systemd/процесса + health-check `/healthz` |
| `logs` | `journalctl -u peakflow-bot -f` или `tail -f logs/bot.log` |
| `backup` | Бэкап БД (`.backup`) + `.env` в `backups/` (хранит последние 10) |
| `restore` | Восстановление из последнего бэкапа |
| `doctor` | Проверка venv, зависимостей, `.env`, сервиса, `/healthz` и HTTPS |
| `caddy` | HTTPS для Mini App: Caddy + Let's Encrypt по домену из `WEBAPP_URL` |
| `uninstall` | Остановка и удаление сервиса (с подтверждениями) |
| `help` | Справка; флаг `--no-color` отключает цвета |

systemd-юнит — `peakflow-bot` с `Restart=on-failure`, `RestartSec=10`,
`ExecStart=.../.venv/bin/python bot.py`. HTTPS обеспечивает `deploy/Caddyfile`
(`reverse_proxy 127.0.0.1:$WEBAPP_PORT`) через `./manage.sh caddy`.

Новые зависимости SP1: `fastapi==0.141.1`, `uvicorn==0.52.4`; для тестов —
`httpx==0.28.1` (`requirements-dev.txt`).
